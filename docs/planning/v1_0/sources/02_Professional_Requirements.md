# 02 — Professional product requirements

**Version:** 1.0  
**Date:** 29 October 2026  
**Status:** Design handoff baseline - implementation and device validation pending  
**Product:** New mobile DJ application; no Mixline reuse  
**Platform direction:** Android first; Galaxy S26 Ultra is the confirmed first test device (current software reported, not inspected)  
**Owners:** Product lead, audio lead, mobile lead, design lead and QA lead

## 1. Requirement contract

The intended product is a complete mobile performance instrument: quick to start, deep enough for professional preparation and live creativity, and dependable during a set. The user confirmed that external-controller integration is excluded. External MIDI/HID DJ controllers and their mapping therefore do not belong in this baseline. DVS/timecode control is proposed as part of that exclusion and should be confirmed. USB audio interfaces and dedicated DJ splitters are explicitly allowed. Microphone functionality is selected; exact supported microphones, speaker routes and external displays still require a hardware matrix.

Every “shall” below expresses a proposed technical acceptance contract for the selected feature scope. This handoff is ready for design; implementation and test evidence are subsequent work. Two decks are the proposed default visible workspace; four-deck performance remains a selected advanced capability. Video mixing, karaoke, broadcasting and third-party plugin hosting are selected requirements. Lighting is excluded. Specific mobile formats, compatible plugins and device tiers remain to be proven, and a missing dependency must be reported rather than silently deleting a selected feature.

The owner confirmed a local Android version first and AWS expansion later. No required LAN/cloud server, AWS account or cloud trial belongs in the local-version dependency chain. The future AWS target is about US$35/month excluding ParDay AI-provider charges; it is a planning target, not spending authorization or a hard cap. Online source operations, broadcasting and optional AI remain independently network-dependent. Preserve the requested local link-to-file feature and report source-specific feasibility gaps rather than silently replacing it with a mandatory cloud service.

Professional capability is measured through completed workflows, accurate timing, audible results, usable controls and recovery. A control that animates without driving the engine does not satisfy a requirement. An engine function without a usable and accessible control does not satisfy the corresponding product workflow.

## 2. Gate vocabulary

G0 establishes the decision baseline. G1 proves audio feasibility. G2 is a working vertical slice. G3 is core performance beta. G4 completes advanced performance. G5 covers source/provider and ParDay integrations. Cloud-specific G5 cases apply only when the later optional AWS extension is evaluated. G6 establishes release candidacy. G7 is the personal installed release. G8 is maintenance and optional community readiness. G3 is not the full requested final product. The user has selected all discussed professional modules except lighting for the complete target. G7 cannot be described as that complete product with selected modules missing, but it does not wait for an AWS extension. Exact provider coverage, compatible plugin formats and certified device combinations remain unresolved implementation constraints.

In the matrix, a gate is the earliest evidence checkpoint. All selected release requirements must also pass regression at G6. QA identifiers are stable test-case references for the quality plan; tests must assert observable behavior rather than repeat implementation code.

## 4. Selected specialist and assistant requirements

**FR-045 — Video mixing:** selected. Support authorized video decks, visual crossfades, linked/unlinked audio-video behavior and visual effects, with external display on named supported routes. Document 15 defines the codec, audio-clock, seek, visual fallback, thermal and output contracts. Owner: Audio/Video + Platform. QA-FR-045 and the AV cases in Document 15. First feasibility G1; integrated evidence G4; release regression G6.

**FR-046 — Karaoke/broadcast:** both selected, with separate submodule acceptance. Karaoke includes singer rotation, authorized timed lyrics/media, mic integration and supported output. Broadcasting includes eligible mix encoding, explicit destinations/start/stop, protected credentials, visible connection state and independent failure handling; camera/visual overlays require their own resource profile. Document 15 defines these contracts. Personal/private practice does not grant internet broadcast rights. Owner: Audio/Video + Integrations. QA-FR-046 plus AV cases; G4/G5, regression G6.

**FR-047 — Third-party plugin hosting:** selected; lighting is explicitly excluded from this requirement and the product. Support at least one genuinely third-party, Android-compatible effect format/path after feasibility, distribution and licence review. Built-in effects alone do not satisfy hosting, and desktop plugin binaries are not presumed compatible. Versioned ABI, latency reporting, resource budgets, failure isolation, preset recall and allowed installation path are required. Document 15 provides the feasibility and acceptance plan. Owner: Architecture + Audio + Security. QA-FR-047 plus AV cases; first feasibility G1, integration G4, release G6.

**FR-048 — ParDay assistant:** selected. Provide a provider-neutral assistant for eligible local-library search, crate preparation, readiness diagnosis, transition proposals and optional rehearsal and selected armed assisted performance. The local validator enforces source permissions, user authority, fresh deck/session state and bounded actions; a model never drives the audio callback. Option C is confirmed: preparation assistance plus explicitly armed bounded transitions/automix and immediate manual takeover. Before a concrete plan is armed, live behavior remains read/propose. Owner: AI + Product + Security + Audio. QA-FR-048, AI-001 through AI-024 in Document 13; deterministic harness G2, cloud integration G5, release G6.

**FR-049 — Music discovery and acquisition:** selected in-app link-to-file acquisition, including the requested unofficial Spotify/YouTube downloader capability. Provide Find a playable version across catalogs, local media and acquisition adapters. Evaluate an own/self-hosted extractor and third-party integration as concrete candidates; Document 16 separates technical verification, provider access, content rights and distribution review. An official API is not a universal technical prerequisite. Preserve recording/version identity, actual media origin, provenance and operation-specific permissions. A URL/search result or streaming offline cache is not treated as an exportable music file. No named adapter is declared working or release-cleared before evidence exists. Owner: Integrations + Data + Security. QA-FR-049, SRC-01 through SRC-12 in Document 14, and DLA-01 through DLA-20 in Document 16; local import G2, admitted provider workflows G5, release G6.

## 5. Cross-cutting acceptance rules

Each test result records device/OS, audio route, sample rate/buffer, workload, media corpus, thermal condition and software versions. Performance targets live in the audio/quality documents; a single fast demonstration does not certify a platform. Differences between devices and source providers must be visible in the capability matrix.

Library editing, artwork decoding, analysis, stem generation, network work and recording writes must not block the real-time audio callback. UI animation follows the audio clock; it never becomes the clock. Operations entering the engine include stable deck identity and ordering so rapid gestures cannot affect the wrong deck after focus changes.

A full release review traces every selected FR to implementation, test evidence, known limitations and user documentation. A feature is complete only when success, loading, unavailable, error, cancellation and recovery states are implemented. Nothing is declared finished because an AI-generated screenshot shows the control.
